# TownSquare

TownSquare is a social web application where users can create and follow **realms** (topic-based communities), write posts, comment, and like/dislike posts. The project was built for the Web Applications course (5th semester, Computer Science).

## Features

- Sign up and log in with email and password (Better Auth)
- Roles (`user` / `admin`) and a separate admin dashboard at `/admin`
- Create, browse and follow realms
- Posts in realms with comments and likes/dislikes
- Leaderboard, user profiles and settings
- Search realms and posts from the navigation bar

## Getting started

### Prerequisites

- Node.js (LTS)
- pnpm
- A Cloudflare account (only needed to generate migrations and deploy)

### 1. Install dependencies

```bash
pnpm install
```

### 2. Environment variables

Create a `.dev.vars` file in the project root (used by the Worker locally):

```env
BETTER_AUTH_SECRET=<a long random string>
BETTER_AUTH_URL=http://localhost:5173
```

Generating new migrations with Drizzle also requires a `.env` file:

```env
CLOUDFLARE_ACCOUNT_ID=<your account id>
CLOUDFLARE_DATABASE_ID=<D1 database id>
CLOUDFLARE_D1_TOKEN=<API token with D1 access>
```

> Do not commit `.dev.vars` or `.env`.

### 3. Database

Create d1 database:

```bash
wrangler d1 create townsquare-db
```

wrangler d1 create townsquare-db
Apply the migrations to the local D1 database and fill it with test data:

```bash
pnpm migrate:dev
```

```bash
pnpm seed
```

The seed script ([src/db/seed.ts](src/db/seed.ts)) creates test users (including one admin), realms, posts and comments.

### 4. Start the dev server

```bash
pnpm dev
```

Open the URL shown in the terminal (usually `http://localhost:5173`).

## Testing

Integration tests use [Vitest](https://vitest.dev/) with [`@cloudflare/vitest-plugin`](https://developers.cloudflare.com/workers/testing/vitest-integration/). They run inside the Workers runtime against a **local, empty D1 database**, so they never touch the real database on Cloudflare and need no tokens.

```bash
pnpm test
```

- `vitest.config.mts` sets up the test Worker and the `DB` binding
- `test/apply-migrations.ts` creates the tables from the migrations in `drizzle/` before the tests run
- `test/helpers.ts` contains helpers to reset the database and create users, realms and posts
- Tests live next to each feature in `src/features/<feature>/__tests__/*.test.ts` and test the full chain controller → service → repository → database

## Project structure

```
TownSquare/
├── drizzle/              # SQL migrations generated by drizzle-kit
├── lib/guards.ts         # Access control (requireUser, requireAdmin, ...)
├── public/               # Static files
└── src/
    ├── worker.tsx        # Entry point: middleware, API routes and pages
    ├── app/
    │   ├── layouts/      # AppLayout, AuthLayout, AppInfoLayout
    │   └── pages/        # Pages (home, realms, leaderboard, user, ...)
    ├── auth/             # Better Auth configuration and middleware
    ├── db/
    │   ├── schema/       # Drizzle schema (auth, realm, post, comment, message)
    │   └── seed.ts       # Test data
    └── features/         # Functionality split by domain
        ├── auth/
        ├── comments/
        ├── global/       # Shared components (header, navbar, sidebars, footer)
        ├── posts/
        ├── realms/
        └── utils/        # Shared helpers (Result, useFetch)
```

Each feature follows a layered architecture:

```
routes → controller → service → repository → database
```

- **routes** define the API endpoints
- **controller** handles the request and response
- **service** contains the business logic
- **repository** talks to the database through Drizzle
- **components / hooks / api** are the client side of the feature

## API

All endpoints live under `/api/v1`.

| Method | Endpoint                      | Description                                 |
| ------ | ----------------------------- | ------------------------------------------- |
| GET    | `/api/v1/users`               | Get all users                               |
| GET    | `/api/v1/users/:id`           | Get a single user                           |
| GET    | `/api/v1/users/name/:name`    | Get a user by username                      |
| GET    | `/api/v1/users/:id/admin`     | Admin information about a user              |
| GET    | `/api/v1/posts`               | Get all posts                               |
| GET    | `/api/v1/posts/:id`           | Get a single post                           |
| GET    | `/api/v1/realms`              | Get all realms                              |
| POST   | `/api/v1/realms`              | Create a new realm                          |
| POST   | `/api/v1/realms/check-follow` | Check whether the user follows given realms |
| GET    | `/api/v1/realms/:realmId`     | Get a single realm                          |
| \*     | `/api/auth/*`                 | Better Auth (login, sign-up, sessions)      |

## Deployment

1. Set secrets in Cloudflare:
   ```bash
   wrangler secret put BETTER_AUTH_SECRET
   ```
2. Apply migrations to the production database:
   ```bash
   pnpm migrate:prod
   ```
3. Build and deploy:
   ```bash
   pnpm release
   ```
